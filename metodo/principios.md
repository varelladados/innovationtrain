# Princípios — o que é permanente no método

> Isto não é uma lista de funcionalidades. É o que é estratégico e permanente
> no método, contra o que é tático e vai mudar de nome, de ferramenta, de
> formato — sem nunca deixar de ser isto. As regras de
> [`regras.md`](regras.md) são a forma operacional destes princípios; a
> [`taxonomia.md`](taxonomia.md) é o vocabulário.

## 1. Toda ideia tem o mesmo direito de virar algo

Uma nota de voz gravada no trânsito tem o mesmo direito de virar produto que uma
ideia lapidada numa planilha. O método não julga a origem — julga se o material
amadureceu o suficiente para dar o próximo passo. Por isso: capturar primeiro,
classificar depois, sempre.

## 2. Nada avança sem rastro

Todo item tem identificador, data, origem e link de volta. Um sistema sem
proveniência não escala: ninguém confia numa ideia sem saber de onde ela veio, e
ninguém consegue evitar redescobrir a mesma coisa duas vezes — duas
implementações do mesmo painel, dois clientes para a mesma API, escritos sem
saber um do outro. Rastro não é burocracia; é memória que substitui a
necessidade de lembrar.

## 3. Cinco estágios, cada um com uma pergunta

Captura, nota, ideia, funcionalidade, projeto. Cada estágio existe para reduzir
o atrito até o próximo — não para impor processo por impor processo. Se um passo
não muda a decisão de avançar ou não, ele não pertence ao método. As perguntas
de cada passagem estão em [`classificar.md`](classificar.md).

## 4. Toda etapa pode terminar em "matar", e isso é sucesso

Um método que só sabe avançar item acumula lixo. Decidir que uma ideia não vale
mais a pena, ou que um projeto deve ser encerrado, é o método funcionando — não
uma falha dele. Encerrar é mover para o histórico com o motivo escrito, nunca
apagar ([regra 1](regras.md)).

## 5. O específico e o genérico convivem, nunca se confundem

Uma estação carrega voz, humor e vocabulário próprios — isso não é ruído, é
identidade, e não deve ser apagado para "parecer profissional". Mas o que é
mecânico dentro dela pode, e deve, virar algo que qualquer outra estação
reaproveita sem aprender esse vocabulário primeiro. As duas coisas não competem:
uma alimenta a outra. É por isso que nenhum nome de estação fica escrito no
código — ele vem da configuração de cada uma.

## 6. Promoção se prova, não se declara

Um padrão só sobe de uma estação para o método depois de provado em uso real,
mais de uma vez, em contexto diferente — nunca por achar que "isso é genérico".
Generalização prematura custa mais caro que a duplicação temporária que ela
tenta evitar. O critério está em [`promocao.md`](promocao.md).

## 7. Nunca inventar o que só o dono sabe

Mercado, números, decisão de marca, direção de produto — o método estrutura a
pergunta, mas não responde por quem só o dono da ideia pode responder. Uma
suposição marcada como suposição é honesta; uma suposição disfarçada de fato é
a forma mais rápida de perder a confiança no sistema inteiro. Quando falta o
dado, a resposta é uma pendência, não um palpite.

## 8. O produto é o próprio motor, não uma entrega isolada

Cada projeto é um produto em potencial — mas o valor acumulado está no motor que
os produz em série: a taxonomia, as passagens, os padrões promovidos. Quem
constrói uma coisa boa uma vez teve sorte; quem constrói várias, repetidamente,
tem um método.
